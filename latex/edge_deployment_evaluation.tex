\subsection{Edge Deployment Evaluation}
\label{subsec:edge_deployment}

We evaluate the computation stage of the SMCC pipeline on Raspberry Pi 4 and
Raspberry Pi 5 devices. The deployed workload replays precomputed flow-feature
rows from the held-out test split and applies the generated rule policy on the
device. The language model, embedding model, vector store, and refinement loop
remain offline. This isolates the runtime cost that an IoT gateway would incur
after receiving a policy update.

The benchmark compares three detectors under identical splits. The LLM policy
uses the canonical JSON rule artifact emitted by the offline stage. The
Decision Tree and Random Forest baselines are trained before the timed region
and then evaluated on the same rows. Each detector runs in two modes. The
streaming mode evaluates one flow at a time and represents live gateway
operation. The batch mode evaluates groups of flows and represents the maximum
throughput available when flows can be buffered.

For each device and condition, we report median, interquartile range,
95th-percentile, and 99th-percentile latency in milliseconds per flow. We also
report throughput in flows per second, peak resident memory, CPU time per
1,000 flows, maximum CPU temperature, ARM frequency, and throttling status.
Power is not estimated from these counters. CPU time, frequency, temperature,
and throttling are treated as software telemetry proxies for resource pressure,
and direct energy-per-flow claims require an external power meter.
